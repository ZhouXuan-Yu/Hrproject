# 智能招聘系统上线安全与性能治理方案

## 1. 目标与上线结论

本项目处理员工信息、候选人联系方式、简历原件、招聘需求以及第三方 AI 凭证，生产环境按高敏感 HR 数据系统治理。当前 `docker-compose.yml` 仍定位为开发/联调环境，不能直接作为生产部署基线。生产上线必须通过本文的 P0 闸门，并在 HTTPS 反向代理、密钥注入、数据库备份和监控完成后再切流。

本次实施范围：

- 后端认证会话、CSRF、CORS、JWT 退出吊销和安全响应头。
- 生产配置默认值拒绝、健康检查脱敏、敏感日志清理。
- AI 代理的角色和工作流边界。
- 用户管理、认证初始化和员工数据读取的查询优化。
- 基于现有表结构和查询条件的复合索引迁移。

## 2. 威胁模型

| 风险 | 保护对象 | 主要控制 |
| --- | --- | --- |
| 越权查看联系方式/简历 | 候选人 PII、简历原件 | RBAC + 数据范围 + 下载接口二次校验 + 审计 |
| XSS/令牌窃取 | 登录会话 | HttpOnly/Secure Cookie、CSRF、CSP、禁止 localStorage 保存 JWT |
| 暴力破解和验证码滥用 | 用户账号、重置流程 | Redis 计数、IP 与账号双维度限流、验证码不写日志 |
| AI 数据外泄 | JD、候选人画像、供应商密钥 | AI 代理角色校验、工作流白名单、内部服务鉴权、密钥不回传 |
| 恶意上传 | 服务器文件系统、解析器 | 大小/扩展名/MIME/魔数校验、随机文件名、隔离目录、下载鉴权 |
| 数据库泄露或破坏 | 招聘业务全库 | 最小权限账号、参数化查询、备份恢复演练、慢查询监控 |
| 生产误配 | 密钥、跨域、调试信息 | prod 启动 fail-fast、环境变量/密钥管理、禁止默认值 |

## 3. P0 上线闸门

1. `SPRING_PROFILES_ACTIVE=prod`，JWT、密码盐、配置加密密钥、数据库密码、Redis 密码均由密钥管理系统或受保护环境变量注入，禁止使用仓库默认值；JWT 密钥至少 32 字节随机值。
2. 通过 HTTPS 反向代理访问，生产 CORS 只允许明确的前端 Origin；开启 Secure Cookie、HSTS、CSP、Clickjacking 和 Referrer-Policy 防护。
3. JWT 只通过 HttpOnly Cookie 传输，登录响应体不返回令牌，前端不再把令牌写入 `localStorage`；登出将当前令牌加入 Redis 吊销列表，直到令牌过期。
4. AI、候选人联系方式、简历下载、导出、配置凭证和用户管理接口完成角色授权；员工只能访问自身员工档案及业务允许的非敏感数据。
5. 登录、找回密码和 AI 调用具备限流；验证码、手机号、邮箱、供应商密钥和完整异常堆栈不得进入业务日志或健康接口响应。
6. 上传接口限制请求体和文件大小，校验扩展名、MIME 与文件魔数，并将文件存储在非静态目录；生产环境完成备份、恢复、审计和告警演练。

## 4. 数据库性能方案

### 已实施的低风险优化

- 用户管理改为数据库分页和独立 `COUNT`，不再把全部用户加载到 JVM 后手工截取。
- 用户列表的部门、岗位名称改为按当前页批量读取，消除逐行查询。
- 注册、首次设置和初始化状态使用 `COUNT`/`EXISTS` 语义，不再调用 `findAll().size()`。
- 员工列表继续使用数据库分页；员工标签改为按当前页员工 ID 批量读取，避免一行一查。
- 新增 V4 复合索引，覆盖逻辑删除、状态、外键和时间排序的实际组合。

### 后续必须用真实数据验证

1. 对人才库、需求候选人、面试日历、仪表盘和用户管理的慢请求记录 SQL、执行时间、扫描行数和返回行数。
2. 对新增索引逐条执行 `EXPLAIN`，确认命中索引且没有因为低选择性导致优化器退化；不要盲目继续加索引。
3. 配置 Hikari 活跃连接、等待连接、超时和数据库慢查询告警；根据生产并发压测结果调整连接池，而不是单纯提高上限。
4. 缓存键必须包含用户、角色和数据范围；涉及权限的数据不能共享不带用户边界的公共缓存。写操作要精准失效关联列表。
5. 长文本简历和 AI 画像不要进入列表查询，详情页按需读取；导出和 AI 计算使用异步任务并设置上限。

## 5. 观测、审计与回滚

- 记录登录成功/失败、登出、权限拒绝、联系方式查看、简历下载、候选人导出、AI 工作流调用、配置修改和管理员操作，日志只保留脱敏标识。
- 指标至少包含 401/403、登录失败率、重置验证码失败率、上传拒绝率、AI 失败率、接口 P95/P99、慢 SQL、连接池耗尽和 Redis 不可用。
- 数据库迁移先备份并在影子库执行；索引迁移失败时只回滚本次索引，不回退业务数据。应用发布保留上一镜像和上一配置版本。
- 上线前完成：备份恢复、令牌吊销、越权访问、跨域、CSRF、上传恶意文件、AI 工作流越权、限流和审计日志验收。

## 6. 当前剩余工作

本次代码修改提供上线前的第一道安全和性能基线，不等同于完成全部合规认证。仍需由部署环境补齐 WAF/反向代理、密钥管理、网络隔离、数据库最小权限、对象存储病毒扫描、日志集中化、告警、备份恢复演练和真实数据压测；未完成这些事项前，发布状态应标记为“候选版本”，不能直接对公网开放。
